# 浏览器与业务后端的契约

[OpenAPI v1](openapi.yaml) 规定派生业务后端需要实现的 HTTP 接口。[前端客户端](../../src/services/session.js) 已实现对应请求。当前后端模板交付 Python 服务层，`main.py` 和 `app/router/` 尚无 HTTP 实现。独立演示页继续使用本地状态。

## 读取当前用户

宿主在启动受保护页面时提供用户令牌。调用方用 `await getSession(userToken, { signal })` 获取 `{ userid, username, ttl }`。令牌只在内存中传递。切换身份时取消旧请求、清除旧用户状态，并按新身份重建工作台。每次受保护操作由后端重新执行身份与业务授权检查。

浏览器向当前平台路径下的 `api/v1/session` 发 GET，无请求体，通过 Authorization Bearer 传用户令牌。网关保留该请求头，剥离平台路径后转发至业务后端的 `/api/v1/session`。例如前端部署在 `/office/` 时，浏览器访问 `/office/api/v1/session`。开发联调可在同源反向代理后运行 Vite 和后端。API 路由应优先于前端的 HTML 回退。

| 后端判定 | HTTP | 前端行为 |
| --- | --- | --- |
| `MiddlewarePlatform.query_user_login(SecretStr(user_token))` 返回有效身份，业务准入通过 | 200 JSON，按契约投影 userid、username、ttl，响应使用 Cache-Control: no-store | 展示当前用户；ttl 单位为秒 |
| 缺少用户令牌，或查询返回 is_logged_in=false | 401 | login_required，交由宿主重新登录 |
| 核实身份后业务准入被拒绝 | 403 | forbidden，显示无权进入 |
| 平台令牌失效、上游不可达或身份服务无法给出可信结果 | 503 | unavailable，保留重新尝试入口 |

传输失败映射为 unavailable；调用方主动取消时保留取消异常。其他 HTTP 状态、HTML 回退或畸形成功响应映射为 unexpected_response。错误分支以状态码为契约，客户端无需解析代理或上游错误正文。平台登录、心跳和平台密钥始终由 Python 服务持有。

## 派生文件业务

文件列表、下载和检索使用已验证的 userid 在后端查询用户文件等级，并按记录授权过滤。等级 0 有效；空等级表示没有授权。入库、删除申请由业务服务根据已授权记录生成，前端通过派生平台的记录 ID 提交操作、读取申请状态；人员身份与文件实例由后端核实。发布成功只表示申请已送出，审核结论以消费并持久化的反馈为准。发送结果不明时按原申请对账。平台心跳、pull、ack、钉钉出口和数据库连接全部保留在服务端。具体记录字段、路由和幂等规则在对应业务专题定义。

## 联调验收

1. 运行派生后端及同源代理，以测试用户从宿主进入；检查请求路径、200 JSON、缓存头及显示的用户名。仅检查令牌是否存在，避免记录其值。
2. 用失效用户令牌、无准入权限的测试身份及暂停的身份依赖分别验证 401、403、503。后端平台登录失败按依赖故障处理。
3. 在子路径构建上刷新深层页面，确认会话请求仍到达同一平台 API。退出或切换账户后核对工作台缓存已经清理。

单独验收前端适配器可在模板根目录运行 `npm run check:session`。脚本按根路径和子路径编译客户端，用临时响应验证请求、身份字段、错误状态与取消行为。
